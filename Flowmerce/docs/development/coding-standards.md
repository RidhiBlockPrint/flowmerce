# Coding standards

- **Language:** Python 3.14 (the one version everywhere, ADR 0010). Other languages only as recorded in ADR 0002; anything else needs explicit owner approval first.
- **Style:** PEP 8 enforced by `ruff` (line length 100, rules E,F,I,B,UP,N,S). Run `ruff format` before committing.
- **Naming:** `snake_case` modules/functions, `PascalCase` classes, `UPPER_CASE` constants. Names describe responsibility; no `utils2.py` or `misc.py`.
- **Types:** annotate all public functions and data structures; `mypy --strict` must pass for `src/`.
- **Docstrings:** every module, public class and public function. Explain business rules and non-obvious logic, not the obvious.
- **Errors:** raise specific exceptions with actionable messages (see `ConfigError`). No bare `except:`, no silent swallowing; catch broad `Exception` only at process boundaries and log it.
- **Logging:** use `logging.getLogger(__name__)`; never log secrets, tokens, passwords or customer personal data.
- **Imports:** absolute (`from flowmerce.config import ...`), standard library first, sorted by ruff.
- **Modularity:** one responsibility per file; modules do not import each other's internals.
- **Testing:** new behaviour and bug fixes ship with tests. Unit tests in `tests/unit/`, interaction tests in `tests/integration/`. Tests must not need network or real credentials.
- **Secrets:** environment variables only; `.env` is git-ignored; keep `.env.example` current.
- **Legacy exclusions:** `src/flowmerce/modules/seo`, its tests and `scripts/run_seo.py` are excluded from ruff and mypy in `pyproject.toml` because they were migrated unchanged. New code in those folders should meet the standards; remove the exclusions as files are cleaned up.
- **Navigation (every module, owner rule 2026-11-24):** the left sidebar is the only way between a module's pages and tabs. Do not add a tab strip that repeats it; list each tab in `frontend/src/lib/routes.mjs` (with a `blurb` for a new module and its colour in `globals.css`, `.nav-module[data-mod]`) and name the tab on screen in the page title (`tabLabel`). Tabs inside one record (like the article editor's) are fine.
- **Dashboard colours (every module, owner rule 2026-11-27):** every dashboard uses the theme taken from the CRO Overview, the `--theme-*` colours in `frontend/src/app/globals.css`: `--theme-good` (sage green), `--theme-usual` (amber) and `--theme-low` (salmon) for how a figure did, their `-strong` steps for thin lines and stripes, `--theme-primary` (navy) for the figure in focus and `--theme-primary-soft` for the rest or the comparison, `--theme-peach` and `--theme-neutral` for longer scales. Draw rings, bars, meters, chart lines and day tiles with these; keep text in the darker `--ok` / `--warn` / `--crit` inks; brand series keep the brand colours. Never write a new hex colour for a chart in a component.
- **Page layout (every module, owner rule 2026-11-24):** no empty space above, under or beside a section. Sections side by side end level (the shorter column's last section grows to fill), a short panel beside a long one travels with it (sticky), and an empty state is one line, not a large blank card. Use the shared layouts in `frontend/src/app/globals.css` (`.grid.main-side`, `.grid.side-main`, `.grid.cols-2`, `.ov-two`, `.calwrap`, `.editor-layout`), which already follow this; never give a layout of sections `align-items: start`.
- **Documentation:** any file added, moved, changed or removed updates `docs/FILE_REGISTRY.md`, `docs/architecture/folder-structure.md` (if structure changed) and `CHANGELOG.md` in the same change.

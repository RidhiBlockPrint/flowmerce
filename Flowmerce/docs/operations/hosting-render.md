# Hosting the live app on Render (free plan)

Status (2026-11-18): set up and tested in CI (job `Hosted container`). Not live until the owner completes the steps below.

This runs the **real** Flowmerce (live Shopify, Supabase and Google data) on the internet, so it is protected:

- **Sign-in on every page and API call.** A Flowmerce sign-in page (`/login`) over HTTPS. Username `admin`, password generated by Render. A signed, HttpOnly session cookie lasts 12 hours, or 30 days with *Keep me signed in*. Five wrong passwords from one address pause sign-in for 15 minutes. *Sign out* is in the account menu at the bottom of the sidebar. Gate: `frontend/src/middleware.js` and `frontend/src/lib/session.mjs`; page: `frontend/src/app/login/page.jsx`. Without a password set, the container refuses to start.
- **The Python API is not reachable from outside.** It listens only inside the container (`127.0.0.1:18787`); the Next.js frontend on Render's public port is the one way in.
- **Keys stay out of GitHub.** You enter them in Render's dashboard. The image build ignores `.env`, `secrets/` and `data/` (`.dockerignore`).
- **The SEO database survives restarts.** Render's free disk is wiped on every restart and deploy, so `scripts/run_hosted.py` restores `data/blog-ops.sqlite` from a private Supabase Storage bucket on start and Litestream copies every change back within seconds.

Files: `Dockerfile`, `.dockerignore`, `deploy/litestream.yml`, `scripts/run_hosted.py`, `scripts/upload_seo_seed.py`, `scripts/hosted_probe.py`, and `render.yaml` at the repository root.

## Free-plan limits

- The app **sleeps after about 15 minutes without visits**; the next visit waits about a minute while it wakes.
- Background jobs (scheduler, shipping refresh) only run while it is awake.
- 512 MB memory, shared CPU. Enough for one person; heavy imports may be slow.

## One-time setup

### 1. Supabase: a private bucket and S3 keys (in your existing project)

1. Supabase dashboard → **Storage** → **New bucket**, name `flowmerce-data`, leave **Public bucket OFF**.
2. Storage → **S3 Configuration** (Settings): note the **Endpoint** (`https://<project-ref>.storage.supabase.co/storage/v1/s3`) and **Region**.
3. Same page → **S3 Access Keys** → **New access key**. Copy the access key ID and secret (the secret is shown once).

### 2. Copy this computer's SEO data up (once)

From the `Flowmerce` folder (PowerShell). Safe while Flowmerce is running; it uses the Supabase keys already in `.env`:

```powershell
.venv\Scripts\python.exe scripts\upload_seo_seed.py --bucket flowmerce-data
```

The hosted app loads this copy on its **first** start only. After that the hosted copy is the one that counts: changes made on this computer are not sent up, and vice versa. Use one copy for SEO work, not both.

### 3. Render: create the service from the blueprint

1. Sign up at render.com (sign in with GitHub) and allow it to see the `RidhiBlockPrint/flowmerce` repository.
2. **New → Blueprint**, pick the repository. Render reads `render.yaml` and asks for:
   - `LITESTREAM_BUCKET` = `flowmerce-data`
   - `LITESTREAM_ENDPOINT` = the endpoint from step 1.2
   - `LITESTREAM_REGION` = the region from step 1.2
   - `LITESTREAM_ACCESS_KEY_ID`, `LITESTREAM_SECRET_ACCESS_KEY` = the key from step 1.3
3. Apply. Then open the **flowmerce** service → **Environment** → **Add from .env**, and paste the contents of your local `Flowmerce/.env`. Before saving, remove the lines `FLOWMERCE_LOGIN_PASSWORD`, `APP_ENV`, `ADMIN_PASSWORD` and `GOOGLE_SERVICE_ACCOUNT_FILE` if present.
4. Google key: **Environment → Secret Files → Add**, filename `google-key.json`, paste the contents of `Flowmerce/secrets/google-key.json`.
5. **Manual Deploy → Deploy latest commit** (the first build takes several minutes).
6. Your link is shown at the top of the service page (yours: `https://flowmerce-vzuz.onrender.com`). Sign in on the Flowmerce sign-in page with `admin` and the `FLOWMERCE_LOGIN_PASSWORD` value from the Environment tab (click the eye icon).

## Deploys (CD)

Every push to `main` that touches `Flowmerce/` (except docs and tests) redeploys automatically. CI separately builds the same image and checks the sign-in gate and API (`Hosted container` job). On shutdown Litestream writes its final changes before the container stops.

## Operating notes

- **Change the password:** edit `FLOWMERCE_LOGIN_PASSWORD` in Render (16+ characters) and save; Render restarts the app and every existing session is signed out.
- **Two schedulers:** if the hosted copy and this computer both run with `SCHEDULER=true`, both run scheduled SEO work against their own databases. Set `SCHEDULER=false` on whichever copy you are not using. Shipping refreshes write to the same Supabase tables from both; that is safe but redundant.
- **Live publishing** still needs `ALLOW_LIVE_PUBLISH` and the typed `PUBLISH` confirmation, exactly as locally.
- **Logs:** Render service → Logs. Lines start with `[flowmerce-hosted]`. A warning that `LITESTREAM_BUCKET is not set` means data will not survive a restart.
- **Restore an older state:** Litestream keeps history in the bucket under `flowmerce/blog-ops`; see the Litestream docs for `litestream restore -timestamp`.
- **Turn it off:** Render service → Settings → Suspend (or delete the service). Data stays in the bucket.
